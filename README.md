# 独立多 Agent 协作基础设施

项目提供独立运行的成员、工作组、消息、任务、会议、成果与受管执行接口。核心使用 JavaScript ESM、Node.js 24、官方 MCP SDK、Zod 和 SQLite WAL，不依赖特定 AI 平台的模型、聊天或应用运行时。

当前核心版本为 0.2.21，主要能力包括：

- 可信凭据映射到固定成员实例；基础设施管理员负责登记和吊销，组内 manager 是可以转交的职责。管理员不能代写成员消息、确认或会议意见。
- 多个独立工作组与任务；私信和广播按实际收件范围授权。消息保存、接收者实际取回、接收者确认和关联回复分别持久记录。
- 活跃客户端可建立有界收件等待；等待由时间、消息数、调用数及显式停止限制，只返回当前身份在本组获准接收的消息。断线、重启或未知响应保留原请求，不自动重开或消费第二次。它维持已有 MCP 调用，不能唤醒已结束或关闭的平台会话，收到工具结果也不会代填成员确认、模型执行或业务成功。
- 每个任务具有负责人、参与人和明确文件权限；组内 manager 不默认获得全部任务文件。规范路径、真实路径和文件身份校验限制任务范围，旧目录不会被接管。
- 共享成果保留作者、来源、内容哈希和各成员自己的评审；引用必须来自实际读过且允许共享的记录。有限上下文读取不会代替成员确认或共同同意。
- 多人会议具有参与人、轮数、总发言数、截止时间和停止策略；完成条件明确记录，每位成员仅提交自己的发言与评审，不自动生成共识。
- 原生会话绑定分别记录组、任务、成员实例、平台、产品模式、原始字段、目录和证据来源。成员自报编号不会提升为运行时验证，消息、本地任务和连接编号不会充当平台会话编号。
- 独立持久调度分别记录执行请求、唤醒、worker、平台进程、模型处理、回复与业务结果。正式执行需要匹配产品模式的受管接口；未知、超时或进程退出保留状态，不自动重复投递。历史独立 CLI 适配器保留兼容，当前桌面协作开发不依赖这条路线。
- 文件工具每次调用重新核对当前任务、成员和文件权限；任务工作目录、模型工具权限、独立文件执行器的操作系统隔离和整个平台的操作系统隔离分别记录，后两项不会因目录或工具限制而自动提升。

内容开发使用同一 brief 的显式阶段合同，分别绑定角色、任务、原始成果、媒体版本与质量证据。受控回收区分已知字节 pin 与新结果回收；本地剪辑、字幕和配音保持准确工具与输入约束。独立三阶段专家合同支持脚本、评审修订和复审，与一次返工预算及原五工具权限分开记录。源码实现、离线合成验证、真实平台执行和业务质量分别验收，不由进程退出、文件哈希或成员声明自动提升。

千问平台媒体适配器提供独立的可信宿主入口，固定 MiniMax H3 与 Speech 2.8 HD 的正式媒体契约，复用既有 HTTPS 回收限制。任务目录身份、精确请求批准、跨进程提交占位、内容防重和总请求预算分别校验；默认生成预算为零。只读凭据接受、请求指定型号、服务实际回传型号、原生任务状态、技术解码与人工影音验收分列记录。平台支持 OpenAI 兼容格式不代表提供全部 OpenAI 端点，媒体适配按其实际接口实现，不扩大成员工具权限。

核心任务的独立媒体桥接默认关闭，启用只能来自可信宿主准确配置。独立 worker 的 binding v2 固定逻辑任务、物理目录身份、输入版本与负责人修订号；worker 通过本人 MCP 领取、实际读取并提交。可信宿主另行准备绑定源码、配置、输入、模型、动作、期限和总预算的 grant。核心与 adapter 的持久意图以两个阶段关联，中断保留 unknown，不宣称跨存储原子性。原独立 CLI v1 和旧成员工具合同保留。API 与 CDN 的显式代理配置分别传播，直接路由的 DNS 明确阻塞发生在调用占位前。

v2 的 API 凭据、原生回执与签名来源合同位于宿主私有运行区；共享 work/files 仅保存白名单安全摘要，MP4 与 MP3 分别直接落同任务 outputs/files 并核实际 SHA。平台状态、回收、核心登记和业务质量分别记录；媒体签名不证明解码、完整视听或业务完成。一次任务的有界 worker 支持准备、待宿主批准及有限状态查询，错误或 unknown 停止；已有 OS 文件准备意图时拒绝回退宿主媒体读写，不外推平台 OS 或网络隔离。

认证端点可由可信宿主显式配置固定本机 CONNECT 隧道，隧道中继续校验目标 TLS 主机和证书，CONNECT 明文不携带 API 凭据。未配置时保留原直连公开 DNS 限制，不自动读取或修改系统代理。媒体下载具有独立的显式无认证 CDN 隧道策略；精确来源合同、主机、URL 摘要、大小与总时限共同限制回收，默认直连守卫保持。代理模式不宣称校验了代理端 DNS 的公开 IP。

视频成功来源只持久保存于任务私有 work，普通结果返回合同路径和摘要。独立回收无需凭据，不查询平台或生成模型；自动回收共用相同实现。回收按原生任务和总下载预算持久防重，未知结果保留部分文件且不自动重试。落盘文件另行读回核对大小和 SHA；模型终态与媒体回收状态分别保存，回收失败不覆盖已成功的模型状态。以上边界均不代表技术解码、人工影音验收或业务完成。

明确失败的媒体响应仅提取固定来源的错误字段，先在内存遮蔽凭据、认证包装、URL、路径与控制字符，再有界写入任务 work 下的独立诊断文件；普通结果只返回相对路径、文件摘要及字段可用性。成功响应不归档自由文本，不保存完整响应或输入。结构化原生编号与错误码不因偶然的短凭据片段重合而丢失，缺失说明保持空值，原请求预算、状态与防重规则保持。

识别词时码候选必须绑定准确源摘要，显式区分短句相对位置、输入音轨位置和成片偏移；未知时基、非有限值、倒序和越界均拒绝。时码归一化不提升为人工听感或语义正确验收。

WorkBuddy 本地助理独立候选只覆盖[官方消息接口](https://open.workbuddy.cn/docs/openapi)，默认关闭且未注册到核心受管执行路由。应用准入、本人 OAuth、指定 Scope、准确请求批准及持久预算齐备后才允许相应请求；文本发送另外要求新近在线状态。前检只核本机合同和授权元数据，不证明网络或OAuth有效。消息回执不代表模型已经开始或完成，不支持精确原生会话、cwd、专家选择或自动工具审批。增量游标仅表示时间范围，不能证明同会话或本任务回复；owner-wide 历史仍须明确授权。

旧历史模式继续只保存白名单元数据。显式正文策略与准确批准绑定后，候选可保留官方 content 数组的有界纯文本分段及原生消息字段，正文仅存宿主私有库，普通结果返回私有引用、SHA和状态；结构化对象、附件、工具审批及未知格式逐项标记不支持，不猜schema或自动下载。凭据原文与常见编码回显在正文哈希和持久化前拒绝，非法UTF-8、超限和ID冲突不静默截断。原顺序与每次快照保留，native message_id不因相同正文而合并。

历史读取的相同operation不重发；在途或unknown游标保持阻断。只有前次GET已明确成功并私有保存后，另一份准确批准才能在总预算内再次读取同一增量游标，空结果不伪造新ID；每次结果独立保存并检查全局消息ID冲突。不自动生成批准、轮询、分享owner-wide正文或将assistant角色认定为任务已处理。纯文本私有读回也不证明实际模型完成或业务质量。

0.1.9 旧版（legacy）兼容通道继续保留其原有版本和权限，包括固定角色 stdio 桥、伙伴通信、任务传输、Cowork 文件交接与既有会话控制。扩展清单仍描述兼容通道；新的独立服务不会替换旧数据库、凭据、任务、失败记录或未知执行。

新增 Windows 原生 AppContainer 文件 worker 由可信 broker 显式注入，仅接收固定的有界文件操作。broker 保管数据库、凭据、任务绑定与实时文件权限；每次实际启动核对进程令牌、专属 SID、完整性级别与能力，再独立读回结果。系统运行时和专属 profile 是必要可读范围，任务文件 worker 的隔离不外推到桌面平台。未配置时沿用 bridge_only 文件检查；显式配置 OS worker 后，缺少可信绑定或验证失败会阻塞，不回退普通文件进程。任务 profile 仅由可信准备步骤创建，重启后的原绑定接管尚未实现，不自动迁移旧任务。

正式执行路由按平台、产品模式和操作保留合同与阻塞原因；本地助理的消息字段、云端原生任务字段与桌面原生会话分开登记。原生产品定时触发、外部API控制与活跃收件分别记账。独立验收观察器可持久记录指定应用的进程观察和只读MCP结果，当前仍缺真实平台开始处理及关闭后对端读回的可信时间链，不能通过G验收。

可信启动可选择独立运行命名空间，并把经审查的预备输入目录映射到新任务。目录真实身份、原输入哈希、旧绑定和已有OS准备意图逐项检查；成员工具不能指定这些配置。默认运行目录保持原行为，未知任务不会被重新接管。

独立市场专家候选使用明确的 CodeBuddy 平台及 `market_expert_cli` 模式。官方包、原专家包、独立profile目录和任务根固定绑定，插件agent通过原插件命名空间选择；受限代理只开放本人原任务与必要输入的读取、开始记录和结果提交。候选保留两轮任务级意图及本地原成功回执，第二轮只恢复相同原生编号；并发、未知和换编号不能重复启动。它未接入core受管唤醒，未验收真实专家加载或模型能力；内置工具和可选Skill脚本不在本候选任务权限内，插件格式校验不证明整个插件功能可用。

专家候选须由可信配置固定精确模型ID，首轮和原号续接均显式传给CLI，并纳入原成功会话绑定；不使用默认路由别名或fallback。每条初始化与助手事件的原生模型字段分别核对，缺失或不符保留unknown并阻断换号重发。公开结果schema没有必需模型字段，不要求调用方补造。协议报告的型号、模型实际服务、专家加载和业务结果分别验收，合成测试不提升真实模型标记。后续评审文本的输入路径应在首轮前固定，不能靠第二轮扩大输入白名单。

工具防护缺省使用明确的strict_mcp_only策略，同时传入空内置白名单和已审查内置工具的显式deny，原会话绑定的字节输入保持原结构。该模式仍拒绝额外发现项；这是此模式的项目策略，不能据此判断所有市场专家的平台兼容性。新增market_expert_preview只做离线证据分析，run在prepare、core预检、意图写入和子进程之前恒拒绝；实际权限保持pending，没有配置或自报verified可开启的生效入口。发现目录、权限声明、实际调用与OS隔离分别记录；被deny的名称出现在目录中不证明获准或越权，规则声明与安装源码阅读不证明历史参数或有效权限。Windows普通子进程stub只证明argv传递层。

五项受限MCP只是本人任务传输的最小集合，原专家加载及其运行最小依赖仍未取证并保持阻塞。humanizer定义的Read/Skill只列为可选候选；规范名、文件真实身份、来源、命令回退、内部fork与继承未验证，不授予实际权限。Read的offset/limit按行号和行数校验，整个固定定义另受64KiB限制；事件自报路径、SHA和approved不代替可信宿主核验。实际tool_use按唯一callId、已发现名称、固定参数范围和主会话来源检查；MCP审计逐项消费匹配，不能用一个条目满足多个调用。该分析发生在事件输出之后，不保证曾事前阻止副作用；即使协议成功也不提升权限、专家或业务验收。原unknown仍依原请求状态和副作用前提处理，不换任务、轮次、会话或策略编号绕过，也不以另建目的解除重发限制。

专家包声明的Skill目录必须位于原包中、具有已固定哈希的定义，名称与目录一致；未声明自定义列表时，仍检查默认目录中的定义，不支持的默认路径显式拒绝。静态检查只报告声明工具、deny重叠以及需复核的hooks、fork和动态命令，不执行定义或扩大权限；旧commands入口保留未覆盖标记，不宣称完整有效加载范围。静态引用、平台注册、实际读取或调用、专家执行分别保留证据；本地会话记录检查只输出有界计数和字段匹配，不返回正文或账号材料，也不以记录缺失、单条用户输入或自报成功解除原未知状态与重试限制。

视频产物接口分别保留生成意图、成员观察、平台原生成字段、实际技能与模型标识，以及broker核验的输出文件元数据。请求型号不充当实际模型身份。视频仅从当前任务输出文件范围登记，按实时ACL分块读回；容器签名、文件哈希、可播放性、完整观看和真实生成分别记账。unknown生成意图只支持本地读取，不实现平台查询或恢复，不自动重新提交。当前大文件接口尚不支持OS文件worker，检测到显式worker或已有OS准备意图就拒绝host回退。

既有视频归档为独立入口和账本，仅当前组manager在拥有任务文件读写权限、实际读过原始派单负责人受控文本结果后，以本人身份登记已存在文件。普通文本发布不能代替任务结果；归档作者与原生产者分列，原任务结果保持原记录。broker重新核对原任务目录、文件身份、单链接、大小、容器签名及总SHA，Windows路径额外拒绝重解析点；归档按当前文件ACL提供同一媒体分块读回。归档不创建或补填生成预留，平台生成号保持null，上游身份和预留验证保持false；任意状态的生成记录与归档互斥，归档后也不能再创建该任务生成意图。源码和离线合成验证不构成真实视频生成或平台来源验证。

评审证据与PNG broker仅提供离线审查接口，不注册新MCP工具，不改变严格默认、原生Read/Skill禁用及预览运行恒拒绝。调用方声明批准、加载成功或新任务/会话编号不能提升实际许可；原请求状态和评审意图分列。固定图片由可信宿主计划绑定任务、成员、来源和最多五帧，返回typed ImageContent前检查目录与文件身份、PNG内容、摘要及次数/字节预算。该端点检查不等于OS隔离、官方专家加载或模型实际看图；失败停止，不自动重试。

PNG原型的context必须由可信宿主认证后提供，字段相等本身不证明认证或当前ACL；原型没有真实认证/ACL联查。读取次数、已读集合和失败阻断只属于当前对象，重建或重启不会持久保留预算或未知状态。真实注册前仍需接入既有持久权限与审计并独立验收，本轮不实现该运行路径。宿主为检查Windows重解析属性启动有界PowerShell进程，不向模型开放PowerShell工具。

开发代码位于 `bridge/src/`，开发脚本位于 `bridge/scripts/` 和 `scripts/`，测试位于 `tests/`。依赖版本由清单和锁文件固定。公开文件采用明确白名单。

原插件加载检查将清单别名、组件来源、插件默认Agent设置、Agent自身skills与插件技能目录分别记录。现有市场计划通过只读调用点附加这些证据，不改变旧模型参数或绑定；宿主解析定义不要求先放开模型Read/Skill。独立manifest诊断计划不因历史unknown全局拒绝，也不会解决它或授权模型。固定版本叶子命令重新解析完整argv，不能假定根选项任意位置可用；裸诊断候选明确不声称none/strict已应用，仍需单次准确审查。退出0与输出明确校验、close完整性分开检查；schema校验不等于原专家装载或执行。

本地测试使用隔离目录和协议 fixture，不调用真实账号或模型。源码实现、离线验证、真实平台与业务完成分别验收；MCP 握手、HTTP 成功、进程启动和自报身份均不能证明真实平台执行或业务成功。独立后台与父客户端断开只构成有限运行证据，不能替代关闭特定 AI 应用后的完整验收。

离线竞争测试分别等待子进程结果、正常退出和关闭，并保留各自证据；结果先到不能覆盖后续非零退出。只有超时或失败才终止仍未退出的测试子进程，随后等待实际关闭并记录退出码，所有等待计时器均清理。测试生命周期修订不代表已查明或修复原生运行时异常。

WorkBuddy 的桌面、CodeBuddy CLI、本地助理与云端模式分别处理；不自动迁移认证或静默替换模式。豆包缺少正式外部会话契约时返回结构化阻塞。Claude 正式接入、认证和执行保持暂停；离线通用结构测试不会提升平台证据。

仓库仅保存经过审查的源码、测试、依赖清单和通用开发说明。个人使用方法、本机配置、部署操作、真实会话与任务回执、日志、截图、数据库、生成产物、密钥和认证文件保留在本地。
