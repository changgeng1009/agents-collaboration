# 独立多 Agent 协作基础设施

项目提供独立运行的成员、工作组、消息、任务、会议、成果与受管执行接口。核心使用 JavaScript ESM、Node.js 24、官方 MCP SDK、Zod 和 SQLite WAL，不依赖特定 AI 平台的模型、聊天或应用运行时。

当前核心版本为 0.2.0，主要能力包括：

- 可信凭据映射到固定成员实例；基础设施管理员负责登记和吊销，组内 manager 是可以转交的职责。管理员不能代写成员消息、确认或会议意见。
- 多个独立工作组与任务；私信和广播按实际收件范围授权。消息保存、接收者实际取回、接收者确认和关联回复分别持久记录。
- 每个任务具有负责人、参与人和明确文件权限；组内 manager 不默认获得全部任务文件。规范路径、真实路径和文件身份校验限制任务范围，旧目录不会被接管。
- 共享成果保留作者、来源、内容哈希和各成员自己的评审；引用必须来自实际读过且允许共享的记录。有限上下文读取不会代替成员确认或共同同意。
- 多人会议具有参与人、轮数、总发言数、截止时间和停止策略；完成条件明确记录，每位成员仅提交自己的发言与评审，不自动生成共识。
- 原生会话绑定分别记录组、任务、成员实例、平台、产品模式、原始字段、目录和证据来源。成员自报编号不会提升为运行时验证，消息、本地任务和连接编号不会充当平台会话编号。
- 独立持久调度分别记录执行请求、唤醒、worker、平台进程、模型处理、回复与业务结果。可信启动可以选择受管 CodeBuddy provider，默认关闭；未知、超时或进程退出保留状态，不自动重复投递。
- 文件工具每次调用重新核对当前任务、成员和文件权限；任务工作目录、模型工具权限、独立文件执行器的操作系统隔离和整个平台的操作系统隔离分别记录，后两项不会因目录或工具限制而自动提升。

0.1.9 兼容通道继续保留其原有版本和权限，包括固定角色 stdio 桥、伙伴通信、任务传输、Cowork 文件交接与既有会话控制。扩展清单仍描述兼容通道；新的独立服务不会替换旧数据库、凭据、任务、失败记录或未知执行。

开发代码位于 `bridge/src/`，开发脚本位于 `bridge/scripts/` 和 `scripts/`，测试位于 `tests/`。依赖版本由清单和锁文件固定。公开文件采用明确白名单。

本地测试使用隔离目录和协议 fixture，不调用真实账号或模型。源码实现、离线验证、真实平台与业务完成分别验收；MCP 握手、HTTP 成功、进程启动和自报身份均不能证明真实平台执行或业务成功。独立后台与父客户端断开只构成有限运行证据，不能替代关闭特定 AI 应用后的完整验收。

WorkBuddy 的桌面、CodeBuddy CLI、本地助理与云端模式分别处理；不自动迁移认证或静默替换模式。豆包缺少正式外部会话契约时返回结构化阻塞。Claude 正式接入、认证和执行保持暂停；离线通用结构测试不会提升平台证据。

仓库仅保存经过审查的源码、测试、依赖清单和通用开发说明。个人使用方法、本机配置、部署操作、真实会话与任务回执、日志、截图、数据库、生成产物、密钥和认证文件保留在本地。
